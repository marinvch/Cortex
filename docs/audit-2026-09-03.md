# Cortex audit — 2026-09-03

Findings from a four-agent parallel review (auditor, qa, product-manager, refactorer) of
`D:\Projects\ai-os` at commit `0496f9c`. Handoff artifact — the source transcripts are not persisted.

**Baseline:** `npm test` 62 tests, 61 pass, 1 skipped. `npm run check:egress` passes. Zero runtime
dependencies confirmed. The skip is `test/paths.test.mjs:36` (symlink escape) — it needs elevation on
Windows, so the security boundary's sharpest test is silently disabled locally while passing in CI.

**Confidence labels:** *Confirmed* = independently demonstrated by two or more agents. *Measured* = one
agent, with numbers or command output. *Unverified* = inferred from code, not executed.

---

## 1. The guard does not cover every write into `.cortex/memory/`

**Confirmed. Severity: highest — this is the product's central safety claim.**

`SPEC.md:102` states: *"One choke point: every write into `.cortex/memory/` passes the guard, which
blocks on detection."* `README.md:84` calls the guard *"the only thing between an agent's observation
and a permanent record in your repository."* Both overstate what ships. Three distinct holes:

**1a — Only a `SessionEnd` hook is registered.** `src/install.mjs:131` (`installHook`) registers
nothing else. Verified against an installed fixture: `hook events registered: ['SessionEnd']`,
`PreToolUse present? false`. An agent that writes `.cortex/memory/gotchas.md` with an ordinary Write or
Edit tool — the most obvious thing to do with a file `AGENTS.md` names explicitly — never reaches
`scan()`. Demonstrated: after a direct write, an AWS key sat in the file unblocked. The guard covers
the `GOTCHA:` transcript-harvest path in `templates/cortex-reflect.mjs:121` and nothing else.

**1b — Only Claude Code has a harvest path at all.** The reflect hook is Claude-specific. A Cursor,
Copilot, or Gemini user emits `GOTCHA:` into a chat window and nothing collects it, while the generated
`AGENTS.md` tells every agent it "is harvested at the end of the session". For three of the four tools
Cortex ships shims for, that sentence is false. `SPEC.md:124` promises a fallback — *"For agents
without a hook system, AGENTS.md instructs the agent to append a gotcha… same file, same guard on the
next cortex-init run"* — and neither half exists in code.

**1c — `templates/cortex-reflect.mjs:81` bypasses `resolveInRepo`.**

```js
writeFileSync(join(root, mod.MAP_REL), markdown);
```

The only write in the codebase that skips the path guard. Every other site resolves first
(`install.mjs:29,30,123,135,164,166`, `memory.mjs:48,72,80`, `plugins.mjs:49,84`, `skills.mjs:25`).
`paths.mjs` is vendored into `.cortex/lib/` (`install.mjs:114`) *specifically* so the hook can use it
after `npx` is gone — and the hook never imports it. `root` comes from `CLAUDE_PROJECT_DIR`; if
`.cortex/map.md` is a symlink, the hook writes through it every SessionEnd. *Symlink exploitation
itself unverified — needs elevation on Windows.*

## 2. `src/memory.mjs` has zero tests, and carries two live defects

**Confirmed.** No `test/memory.test.mjs` exists. Grepping `appendGotcha|initMemory|SecretBlockedError|
MAX_ENTRIES` across `test/` returns one hit — `install.test.mjs:68`, which only asserts the file was
copied. The module holding the guard's sole enforcement call site is unverified.

The guard corpora in `test/guard.test.mjs` test `scan()` in isolation. **Nothing asserts that a guard
hit actually prevents the write.** Reorder `memory.mjs:67-72` so the file is created before the scan,
or swallow the throw, and the whole suite still passes. (Both agents verified it does block today.)

**2a — substring dedupe silently discards new knowledge.** `src/memory.mjs:75`:

```js
if (fingerprint(existing).includes(fingerprint(entry))) return { written: false, reason: 'duplicate' };
```

Any entry that is a substring of anything already in the file — *including the file's own boilerplate
header* — is dropped. Demonstrated against a **freshly initialised** file:

```
append "for humans too"  -> {"written":false,"reason":"duplicate"}
append "Prune freely"    -> {"written":false,"reason":"duplicate"}
```

Gets monotonically worse as `gotchas.md` grows, and recomputes `fingerprint()` over the entire file
once per entry (up to 5× per session).

**2b — `decisions.md` has no write path.** `DECISIONS` appears in exactly two places: the constant and
`initMemory`, which seeds the file. There is no `appendDecision`. Nothing has ever written to it, yet
`README.md` bills it as one of five headline artifacts ("Append-only decision log"). `SPEC.md`'s own
Context section names "a static heading nothing ever filled" as the reason this repo was rebuilt — the
product reproduced its founding bug one file over.

**2c — `MAX_ENTRIES_PER_SESSION` works but is unlocked by any test** (verified: 5 written, 2 skipped).

## 3. `test/guard.test.mjs:131` — literal GitHub PAT, the exact thing the file forbids

**Confirmed. Severity: will break pushes.**

```js
const res = scan('line one is fine\nline two is fine\ntoken ghp_016C7e5c9AbCdEfGhIjKlMnOpQrStUvWxYz12');
```

The file's own header (lines 9–19) says GitHub push protection rejected this file when the strings were
literals, and *"Do not 'tidy' these back into single strings — the push will start failing again."*
Every `MUST_BLOCK` entry uses `mk(...)`. This one does not. `ghp_` + 37 alnum chars is full PAT shape
and matches GitHub's own pattern. It is the only literal of its kind in `src/`, `test/`, `templates/`.

**This is the one item worth fixing before any push.**

## 4. The guard over-blocks on ordinary knowledge

**Measured. Severity: this is how security tooling gets ripped out.**

`src/guard.mjs:120-148` layer 3 harvests values from any file matching `ENV_FILE = /^\.env($|\.)/` —
which includes `.env.example`, whose values are public placeholders by definition. `NON_SECRET_VALUES`
filters only 18 exact words. Against a repo with a normal `.env` plus `.env.example`:

| gotcha | result |
|:---|:---|
| `the dev server runs on http://localhost:3000 — use that, not 127.0.0.1` | **BLOCKED** |
| `put your-api-key-here in .env.example so new devs know the shape` | **BLOCKED** |
| `contact admin@example.com about prod access` | **BLOCKED** |

`README.md:100` argues *"A guard that fires on a commit SHA is a guard developers rip out."* This fires
on `localhost:3000`, and the loss is silent from the developer's side — one line to stderr at session
end.

**The `MUST_NOT_BLOCK` corpus has ten entries and not one exercises layer 3.** Every layer-3 test is a
must-block. The false-positive corpus that `SPEC.md:172` calls load-bearing has its hole exactly where
the layer with no regex to constrain it lives.

## 6. A second `cortex-init` run is not a no-op

**Confirmed by three agents independently.** Run twice into a fresh repo:

```
RUN1: 22 files | RUN2: 24 files
NEW: + AGENTS.md.bak   + .cortex/map.md.bak
CHANGED: []            AGENTS.md byte-identical run1 vs run2? true
```

Both `.bak` files are byte-identical to their originals — `src/install.mjs:29` backs up
unconditionally, before comparing content. Cortex's own `.gitignore` has `*.bak`; **the target repo's
does not, and Cortex never adds it**, so `git add -A` stages the junk.

`SPEC.md:166` lists *"Idempotent | run twice, assert second run is a no-op"* as a verification
requirement. No such test exists — `install.test.mjs:149` only asserts the hook isn't double-registered.
The shims already do it right (`install.mjs:56` compares content and skips); `write()` should too.

|:---|---:|

## 9. The map truncates silently at 8 entries

**Measured, single-source.** `f.exports.slice(0, 8)` / `f.imports.slice(0, 8)` render with no
indication truncation occurred, while Coverage reports "Scanned 11 of 11 source files." In Cortex's map
of its own source:

- `src/map.mjs` has 9 exports; the map lists 8. **`isStale` is missing** — the function the reflect
  hook depends on.
- `src/install.mjs` imports 10 modules; the map lists 8, dropping `./plugins.mjs` and `./map.mjs` —
  real internal edges — because `node:fs`, `node:path`, `node:url` ate three slots.

The module graph of the orchestrating file is factually wrong, in a document whose stated design
principle is *"a map that overstates itself is worse than no map, because agents trust it."* Dropping
stdlib/bare-package imports fixes both problems at once: the internal edges are the graph, and
reclaiming the budget stops most files truncating at all.

**Related, unverified:** `ignoreFilter` (`map.mjs:38-56`) unions `.gitignore` and `.cortexignore` into
one `Set`, so `.cortexignore` cannot "win" anything — `test/map.test.mjs:69` asserts a precedence that
does not exist. It also drops any entry containing `/` (e.g. `src/generated`), since it only compares
single path segments. And Coverage never discloses what was *excluded* by `ALWAYS_SKIP` or
`.gitignore` — `total` is post-filter (`map.mjs:85`), so a repo with `src/build/` loses those files
with no signal.

## What to build, ranked (product-manager)

1. **A universal memory write path** — `node .cortex/lib/remember.mjs "…"`. Any agent that can run a
   shell command records a gotcha through the same guard, dedupe, cap, and provenance stamp. Fixes 1a
   and 1b, gives `decisions.md` a reason to exist, and needs no new machinery: `appendGotcha(root, text,
   {source})` already defaults `source` to `'manual'` and has never been called. **Must be a committed
   local script, not `npx …--remember`** — an npx round-trip is a registry fetch on every gotcha.
   Commits the project to a stable invocation string baked into thousands of `AGENTS.md` files.
2. **Ship a `.gitattributes` for the paths Cortex owns** — `merge=union` on `.cortex/memory/*.md` kills
   the guaranteed merge conflicts on append-only files, and `eol=lf` on `.cortex/**` fixes the same
   defect commit `7be5bc1` fixed for this repo but left unfixed in target repos (a Windows checkout with
   `core.autocrlf=true` flips the whole brain to CRLF). Closes `SPEC.md` open question 3 verbatim.
   Cheapest item on the list. Must be a marker-delimited append with a `.bak`.
3. **`cortex-init --check`** — no writes, exit 0/1: shims present and pointing at `AGENTS.md`, markers
   intact, all of `.cortex/memory/` passes the guard, map staleness. **Staleness should warn, secrets
   and missing shims should fail** — a `--check` that fails on a stale map forces map regeneration on
   every PR touching imports, which is exactly the diff noise to avoid.
4. **Fix the map's truncation and stdlib noise** (finding 9).
5. **Explicitly *not* recommended: an AGENTS.md section filler.** The generated file is 69 lines, a
   quarter of it italic prompts to a human that nobody fills. The tempting fix — a `/cortex-onboard`
   skill that infers conventions — produces exactly the artifact the project's own precedent forbids:
   model-guessed prose about a team's conventions, committed, indistinguishable from prose a human
   vouched for. Gotcha extraction reads explicit markers for this reason. **The gap is template design,
   not a missing feature** — cut the placeholder sections instead.

## Refactor proposals, ranked

Each was checked against existing tests. "No test changes" means the proposal is provably a refactor.

**R1 — Split `buildMap` into analyse/render.** `src/map.mjs:203-300` is one 97-line function doing
gather (206-227), analyse (229-239), and render (241-293). The Coverage guarantees `SPEC.md` calls
load-bearing are string interpolation at 288-292, 55 lines from where the facts are computed. Two costs
fall out: every file is read twice, and `isStale` (`map.mjs:311-315`) renders the entire markdown
document and runs the whole `countLines` pass, then keeps one 12-char hash — on **every** SessionEnd.

Measured on the 2000-file cap case: `scanRepo` 18ms, read+extract ~700ms, `countLines` second pass
~1,100ms, **`isStale` total ~1,700ms**. ~65% of the hook's per-session cost is a redundant read whose
only consumer is a "Largest files" list `isStale` never looks at.

Recommended: `analyze()` returns a model, `renderMap(model)` returns markdown, `buildMap` composes
them, `isStale` calls `analyze(root, {lines:false})`. Expected `isStale` ~1,700 → ~720ms, `buildMap`
~1,800 → ~900ms. **Fully covered by `map.test.mjs:155,171,179,188,199`, `reflect.test.mjs:27,35,46`,
`install.test.mjs:192` — no test needs to change.** One trap: `countLines` returns `0` on read failure
but `''.split('\n').length` is `1`, so the split must carry a `readFailed` flag or unreadable files
silently gain a line and "Largest files" reorders. Add a byte-equality assertion on `buildMap` output
including an unreadable fixture to pin it.

*Rejected alternative worth recording:* replacing the content hash with an mtime/size manifest would
make `isStale` a ~20ms stat walk, but mtime is not a content signal — a fresh clone forces spurious
regeneration — and it breaks `map.test.mjs:188`. That is a behaviour change, not an optimisation.

**R2 — One primitive for writing into the repo.** Five write sites, four different backup policies:
`install.mjs:24-31` backs up; `plugins.mjs:46-50`, `skills.mjs:23-25`, `install.mjs:121-123`
(`vendorLib`) and `install.mjs:133-135` (hook copy) do not. The backup policy is an accident of which
code path a file travels, not a stated rule — which is why finding 7 loses the user's settings and
finding 6 backs up files Cortex owns outright.

Recommended sequence: **first extract `updateSettings(repoRoot, mutate)`** into its own module and
point both callers at it — ~30 lines across two files, deletes the drifted duplicate, and fixes the
`.bak` data loss as a side effect of there being one implementation. Then consider a fuller
`repofs.mjs`. **Add the failing test first** — that a pre-existing `.claude/settings.json` is
recoverable after `--with-plugins` — or "unify the backup rule" has nothing to demonstrate against.
Covered by `install.test.mjs:54,89,134,149` and `plugins.test.mjs:32,42,52,62`.

**R3 — `--dry-run` does not preview a real run.** `install.mjs:64-68` special-cases memory because
`initMemory` (`memory.mjs:42-52`) decides and writes in the same loop, so it cannot be asked what it
would do. Wrong twice, both reproducible: on a fresh repo the dry-run plan says `.cortex/memory/ —
would seed…` where a real run reports two individual files created; on an already-installed repo the
dry run still claims it would seed, where a real run writes nothing. Every other collaborator gets this
right — the shims correctly report `unchanged` (`install.mjs:56-60`).

Recommended: `plannedMemoryFiles(repoRoot) → rel[]` (pure, `existsSync` only) plus `initMemory` writing
what the planner names. ~10 lines, no signature churn, no test edits. **No existing test covers the
defect, which is why it survived** — needs one new test asserting the dry-run plan matches the real
run's report.

**R4 — Pin `memory.mjs` before touching it.** Ranked last as a refactor, but **the tests should be
written regardless of whether the hoist happens** — this is the same gap as finding 2, and it is what
makes every other proposal here riskier than it needs to be. Untested: the dedupe fingerprint, the
session cap (and the fact that blocked/duplicate entries do not consume it, `memory.mjs:91`),
`SecretBlockedError`'s message format, and the exact entry format `\n- ${stamp} — ${entry}
_(${source})_\n` that lands in people's git history.

The inefficiency in the same code: `appendGotcha` calls `collectEnvValues(repoRoot)` — a `readdirSync`
plus a full read of every `.env*` file — **once per candidate**, inside `appendGotchas`'s loop. Since
blocked and duplicate entries never increment `written.length`, the loop is unbounded by the cap: 300
candidates against a 60-line `.env` measured 398ms, nearly all repeated I/O.

### Cross-cutting guardrail — land this before R2 or R4

`VENDORED` (`install.mjs:114`) is `guard/paths/memory/map`, and the vendored copies must be
**import-closed** — they may only import each other, because they run in repos where the rest of `src/`
does not exist. Today only `map.mjs`'s closure is proven, and only incidentally, by
`test/reflect.test.mjs:30`. `memory.mjs` writes directly at lines 48, 72, 80 and is the most tempting
caller for any new shared write helper; routing it through one would silently break every installed
repo's SessionEnd hook. A five-line test — install into a fixture, `await
import(pathToFileURL('.cortex/lib/memory.mjs'))`, call `appendGotchas` — is cheap insurance.

## Where the agents disagreed

Running four independent reviews produced two direct conflicts. Both resolve in the refactorer's
favour, and both would have been easy to get wrong from a single pass:

1. **`map.mjs:183` re-parsing `package.json`.** The auditor filed it as redundant I/O worth removing.
   The refactorer identified it as *load-bearing* — `map.mjs` is vendored standalone into `.cortex/lib/`
   and runs in repos where `detect.mjs` is absent, so sharing a helper would break the hook everywhere
   Cortex is installed. **Do not "fix" this.** It is the clearest example in the codebase of duplication
   that must stay.

2. **The substring dedupe at `memory.mjs:75`.** QA and the auditor both demonstrated it silently
   discarding genuinely new knowledge (finding 2a). The refactorer listed it under *leave alone*,
   arguing it is a deliberate cheap dedupe and changing it alters which entries get written. Both are
   right, and they resolve cleanly: **it is a real defect, and fixing it is a behaviour change, not a
   refactor** — so it needs a deliberate decision, a test written against the intended new behaviour,
   and it must not be swept into a cleanup pass.

A third, softer tension: the PM argued for deleting the plugins feature outright, while the auditor
filed two fixable bugs in it (findings 6, 7). Fixing bugs in code that should be deleted is waste —
decide the feature's fate first.
