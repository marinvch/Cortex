# Plan: two clocks in one repo

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:executing-plans`. Steps use `- [ ]`.

**Goal:** the day a Cortex artifact is filed under is decided in exactly one place per language, and
a test fails if a second clock appears.

**Spec:** none — candidate 7 of the 2026-08-19 architecture review of v2.8.1.

## The finding

`core/date.js` stamps **local** time. `mcp/server.js:27` stamps **UTC**:

```js
const today = () => new Date().toISOString().slice(0, 10);
```

Demonstrated, not theorised — one real instant, in the user's own UTC+3 timezone:

```
01:00 local on 19 August 2026
  server.js:27  new Date().toISOString().slice(0,10)  -> 2026-08-18
  core/date.js  stamp()                               -> 2026-08-19
```

`capture` files through `today()`, so a thought captured at 01:00 lands in **yesterday's**
`daily/` note and yesterday's `inbox/` file. For anyone east of Greenwich this is wrong for the
first hours of every day; west of it, wrong for the last hours.

`server.js:27` is the **only** UTC clock in the repository. `core/memory.js`,
`index/cortex-findings.mjs` and every shell tool stamp local. It is the outlier, not the standard.

## Correcting the review

The review said two tools in one server disagree about the day. They cannot: `capture` is in
`VAULT_TOOLS` and `remember` in `REPO_TOOLS`, and `mcp/server.js:60` gives one process one list or
the other. The bug is real and the fix is unchanged, but it is a **single-tool** bug — `capture`
files to the wrong day on its own terms — not a disagreement inside one process. The disagreement
is across the two roots a person runs Cortex against, which surfaces the same day in two forms.

## The shell half

Four scripts stamp a date, in three format strings for two meanings:

| Site | Call | Meaning |
|---|---|---|
| `tools/cortex-init.sh:17` | `date +%Y-%m-%d` | the day |
| `tools/cortex-scan-projects.sh:20` | `date +%Y-%m-%d` with a literal fallback | the day |
| `tools/server/cortex-cron.sh:39` | `date +%F` | the day |
| `tools/cortex-init.sh:18` | `date +%Y%m%d-%H%M%S` | a unique suffix |
| `tools/cortex-rm.sh:23` | `date +%Y%m%d-%H%M%S` | a unique suffix |

Two of them invent a value when `date` fails, which is worse than failing:

- the `2026-07-01` fallback stamps every project stub with a **hardcoded day in the past**.
  Frontmatter reading `created: 2026-07-01` is not a missing value a reader can spot; it is a
  plausible wrong one.
- the `0` epoch fallback sets `NOW_EPOCH=0`, and `age_days` then goes **negative**, so every dormant
  repo is silently classified as active — the exact opposite of the check.

There is no system Cortex runs on without `date`. The fallbacks defend against nothing and
mis-stamp when they fire.

## Two standalone scripts keep their own copy — by design

`tools/cortex-init.sh` does not source `_cortex-lib.sh`: it is a zero-dependency installer, and
`_cortex-lib.sh:3` says so. `tools/server/cortex-cron.sh` is the same shape — `server-setup.sh:79`
installs it into a crontab where only it and `server-setup.sh` exist on disk, so there is no lib to
source.

That is the slugify situation exactly, and it takes the slugify answer: the copies stay, and a
**parity test** pins them. Hoisting the helper into a lib those two cannot load would break them.

## File structure

| File | Responsibility | Change |
|---|---|---|
| `mcp/server.js` | drop the UTC clock, import `stamp` | modify |
| `core/test/date.test.js` | `core/date.js`'s first direct test | **create** |
| `mcp/test/one-clock.test.js` | `mcp/` defines no clock of its own | **create** |
| `tools/_cortex-lib.sh` | `cortex_today`, `cortex_timestamp` | modify |
| `tools/cortex-rm.sh`, `tools/cortex-scan-projects.sh` | use them; drop both fake fallbacks | modify |
| `tools/test/date-parity.test.sh` | the two standalone copies still agree with the lib | **create** |

`core/date.js` itself does not change. It is already correct; it was the one `core/` module with no
test, which is why the outlier could sit beside it unnoticed.

---

## 1. `core/date.js` gets its first test

**Touches:** `core/test/date.test.js`

- [ ] `stamp` is local, not UTC — assert on an instant whose UTC day differs from its local day, with
      `TZ` fixed so the test means the same thing on every machine.
- [ ] `stamp` pads: a single-digit month and day come out `2026-01-05`, not `2026-1-5`.
- [ ] `clock` is local `HH:MM`, padded.
- [ ] Both default to now and both accept an explicit `Date`, which is what keeps callers testable.

## 2. Delete the second clock

**Touches:** `mcp/server.js`, `mcp/test/one-clock.test.js`

- [ ] Import `stamp` from `../core/date.js` and delete the local `today` helper. The layering already
      permits it — `server.js:9` imports `core/memory.js`.
- [ ] Write the guard: scan `mcp/` for `new Date()` and `toISOString` outside a test. Modelled on
      `mcp/test/vault-is-the-only-door.test.js`, which exists because a module bypassed a guard
      without anyone writing the call.

## 3. One date helper for the shell half

**Touches:** `tools/_cortex-lib.sh`, `tools/cortex-rm.sh`, `tools/cortex-scan-projects.sh`

- [ ] Add `cortex_today` and `cortex_timestamp` beside `slugify`, with the note that two standalone
      scripts carry their own copy and a parity test pins them.
- [ ] Point `cortex-rm.sh` and `cortex-scan-projects.sh` at them.
- [ ] Delete both literal fallbacks. A stamp that cannot be taken is a hard failure, named, not a
      plausible wrong number filed into someone's frontmatter.

## 4. Pin the standalone copies

**Touches:** `tools/test/date-parity.test.sh`, `tools/test/run.sh`

- [ ] Assert `cortex-init.sh` and `cortex-cron.sh` produce the same strings as the lib helpers —
      `date +%F` and `date +%Y-%m-%d` are the same format written two ways, and the test says so.
- [ ] Assert neither script reintroduces a literal date fallback.
- [ ] Register the file in `tools/test/run.sh`.
